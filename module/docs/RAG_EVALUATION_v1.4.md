# 企业 RAG 单次评估 rag-eval-1.4

本版把六维等级评分改为服务端冻结的逐检查项评分，并在页面以固定 0–100% 六轴雷达图展示。它不以“分数更像真实分布”为目标：有证据的回答可以满分，同质量回答可以同分；不同分数只能来自可定位的实际缺陷。

## v3 数据流

1. 服务端仅根据问题和预先指定的任务类型冻结 `checklist`，不根据回答质量改变检查项、分值或适用性。
2. Judge 逐项返回 `met / partial / unmet / undetermined / not_applicable`、判断理由和证据；不输出六维分或总分。
3. 程序按 100% / 50% / 0% 确定性汇总六维及总分。未知保持 `null`；预先冻结的 N/A 在维度内按适用权重归一，整维 N/A 从总分分母移除。
4. 重大业务、安全、权限和核心任务失败继续由结构化门禁阻断；分数不覆盖门禁。
5. 页面直接使用服务端确定性结果绘制雷达图，未知或 N/A 轴不补零、不补满分，图形不完整时不填充多边形。

六维权重保持 20 / 25 / 15 / 15 / 15 / 10。检查项和模板定义在 `contracts/enterprise-rag-checklist.ts`，结果算法在 `client/dashboard/ai-website-preview/enterprise-rag-checklist-skill.ts`。

## 防止虚构差距与重复扣分

- `optionalSuggestions` 是单独的锦上添花建议，不扣分，也不自动形成“可用·待改进”。
- 每个扣分 finding 必须绑定唯一 `rootCauseId`、一个主 `checkId` 和一个主维度；同一回答 claim 不能跨 finding 重复扣分。
- 已支持事实在依据未展示时可形成引用展示问题；partial、unsupported、contradicted、unverifiable 的同一事实不能再以“引用未展示”二次扣分。
- 同一检查项存在多个缺陷也只使用该项三档分值，不叠加成负分。
- 一处明确但不影响任务完成的重复只对应 `clarity_concise=partial`，在当前模板扣 1.5 分；这不是所有轻微问题的通用扣分。

`rootCauseId` 和 claim 坐标只能拦截结构化重复；语义上换说法的重复问题仍需用人工标注集校准，不能宣称完全自动识别。

## N/A、证据和展示

只有服务端冻结 `applicable=false` 的检查项可以返回 `not_applicable`，并使用冻结 `exclusionReason`；模型不得为 N/A 临时附加证据。其他状态必须定位至少一项冻结证据。

雷达图各轴始终按本维得分比例显示，固定 0–100%。图形外继续显示主结论、重大风险、待补证和可选建议；点击轴可查看检查项、原始分、理由及证据。浏览器人工复核暂时仍是 `rag-eval-1.3` 等级式辅助记录，不是 v3 正式人工复核合同。

## 验证边界

`fixtures/rag-eval-1.4/tasks.json` 和 `scripts/rag-checklist-calibration.mjs` 只使用虚构“星舟”资料和固定判断，用于验证公式、版本、证据哈希及 UI 合同；不联网、不调用模型，也不代表真实 Judge 准确率或业务验收。

真实校准仍需获批测试环境、资料、模型预算和独立人工标注，重点核对漏检、过度扣分、模板错配、语义重复扣分和多次运行稳定性。本文件不宣布已部署或已通过正式验收。
