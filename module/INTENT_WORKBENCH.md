# GEO 问题优化工作台

本轮根据用户提供的 `GEO_Intelligent_Workbench_Prototype.html` 实现 React 业务功能。保留 FrontMind 现有导航、字体、公共控件与知识库构建流程。

## 已实现流程

1. 品牌全域词库支持搜索、分类和细分筛选；“选择词条”连续选择，跨筛选保留选择，确认弹窗可以移除问题。
2. 确认问题后进入持久化优化清单，按实际 ID 评估单条或批量问题，不将所选数量替换为列表前几条。
3. 评估呈现六项维度、评分原因、回答要点支撑矩阵、匹配节点与正文证据、诊断摘要。单条可切换下一条，批量逐条展开细则。
4. 生成方案后逐项采纳、不采纳、编辑问题/知识正文/资料待办；知识写入默认不勾选。展示当前动作的规则预估，支持保存草稿和未保存修改保护。
5. 执行仅使用已审核、已勾选动作。结果区分成功、失败、待确认和已撤销；显示执行前后评分与仍未充分支撑的要点。
6. 实际节点变更可定位、搜索、阅读；继续确认、上传资料、管理图片和下载 ZIP 复用原有智能知识库入口。
7. 优化清单、方案、资料待办、执行记录可刷新恢复。支持 JSON 报告下载和存在后续修改时拒绝直接撤销。

## 评分口径

本实现采用可解释的本地规则 `rules_v1`，不接入新模型，也不触发付费供应商调用。六项维度为意图明确度、品牌关联度、决策相关度、问题清晰度、内容独特度及知识支撑初评，平均得分作为问题价值。规则只依据问题文本、当前候选清单和知识正文；没有将模拟搜索热度包装成真实数据。

知识支撑按必要回答要点匹配与问题相关的节点，展示具体正文证据。未覆盖计 0 分、部分覆盖计 50 分、充分覆盖计 100 分，取均值。节点尚未确认，或者句子包含待补、待核验等表述时，不计为充分支撑。创建资料待办、记录来源和加入回答边界本身不等于解决知识缺口。修改正文后分数可能下降，结果按实际内容呈现。

规则评估不是语义模型测评，无法保证医学、资质或法律事实正确，也不能用它替代专业内容审核。后续接入模型时应保留该方法标识、证据和核验边界。

## 真实接口与持久化

新增接口挂载在现有模块 HTTP 入口，自动参与模块业务构建：

| 接口 | 功能 |
| --- | --- |
| `GET /api/modules/brand/intent` | 读取清单、评估、方案、执行记录和当前知识 |
| `POST /api/modules/brand/intent/command` | 加入问题、评估、生成/编辑方案、记录资料来源 |
| `POST /api/modules/brand/intent/execute` | 冻结已选动作，执行并记录重评 |
| `POST /api/modules/brand/intent/rollback` | 检查后续修改后恢复本次内容 |

上线前需对业务数据库执行 `module/schema/20261020_intent_workbench.sql`。它只创建新清单表，不修改原有知识库表和数据。此迁移没有在本轮运行。

所有清单 SQL 读取和写入均限制服务器认证的账户与企业项目。客户端无法覆盖 owner/project。清单使用行锁与单调版本检查，执行冻结动作与请求 ID，短期执行租约防止两个请求同时推进。断线恢复使用原执行 ID；最多等待 120 秒租约释放后继续。已记录的成功动作不重复执行，待确认节点先比对当前正文与执行前后正文。

节点写入复用原有 `getKnowledgeNodeDetails` 和 `saveKnowledgeNodeContent`，保留 generation、revision、stateEpoch、contentVersion、resetRevision、正文规范化与既有工作集校验。不直接覆盖不可变知识快照；编辑后仍需原有知识库流程确认和发布。没有可编辑工作集时只提供问题优化和资料待办。

撤销按动作记录恢复，先检查内容是否已经被其他操作修改。多节点执行和撤销是逐项操作，不承诺跨知识节点的原子事务；异常可出现部分完成，成功/未完成分别记录。撤销失败可在租约过期后重试，已经撤销的节点不重复恢复。

## 入口与生效范围

意图优化列表按新截图布局：顶部生成问题折叠区、搜索/类别/应答状态筛选、问题/分类/应答状态/操作表格。每行操作顺序为“查看词条评估 → 进入应答逻辑 → 修改问题 → 删除问题”。分数进入首个操作后展示，再生成方案和执行，保留既有知识差异对比和批量评估。

「进入应答逻辑」由本包应答逻辑源码承接：独立壳路由含 `response-logic` 页面（“应答逻辑”），点击后保存当前问题上下文并切换到 `BrandResponseLogicEntry` 挂载的应答逻辑工作台（问题内容在工作台内由服务端从 Brand 账本按认证身份重新解析，不信任前端传入文本）。应答逻辑的 REST 端点、材料上传契约与权限边界见 [API 开发说明](API_DEVELOPMENT.md)。修改问题、删除问题、新增问题与生成问题面板仍由宿主经 `ModuleWorkspace.intentCatalogIntegration` 注入（`onEditQuestion`、`onDeleteQuestion`、`onAddQuestion`、`generationPanel` 及按问题 ID 映射的 `answerStatuses`）；当前独立壳尚未注入这些回调，对应按钮禁用、应答状态显示“暂未同步”。回调收到原始完整问题记录，以 ID 对齐，不能按显示行号匹配。本包不伪造已发布应答。

真实 React 业务入口为 `module/client/ModuleWorkspace.tsx` 的 `keywords` / `intent` / `response-logic` 页面。现有 `keywords` 入口直接消费工作台，因此不只是 standalone 页面。`ManagedKeywordTables` 新增可选批量回调，未提供时保持原有宿主的单条选择行为。

`standalone/App.tsx` 增加“优化问题”与“应答逻辑”视图；应答逻辑视图必须从优化问题列表携带问题进入，直接访问时显示引导提示。Dashboard 现有 `ModuleWorkspace` 的 `keywords` 引用会获得工作台；Dashboard 新增独立 `intent` 导航仍需要宿主装配，宿主源码不在本包，不宣称已完成生产集成。

本地运行 `corepack pnpm@10.4.1 dev`，访问 `/?view=keywords` 或 `/?view=intent`。开发模式明确展示“合成演示数据”提示，通过 `standalone/intent-preview.ts` 在 localStorage 保存演示交互。正式构建使用真实模块 REST 接口，不把演示适配器用于正式业务。

## 验证

- 新意图列表通过类型检查、前端构建和 15 项相关测试；1440px/390px 浏览器验证四个操作顺序、其他三个入口禁用边界、分类与应答筛选、非首条问题进入评估及方案、批量评估、页面无横向溢出。
- 知识库变更页新增执行快照对比：逐行标记新增/删除、前后全文和当前正文三种模式。只展示已成功写入或已撤销的节点动作；没有记录的节点展示当前正文；后续修改和撤销状态明确标注。比较读取记录内 before/after，不用最新正文替代历史版本。大文档限制逐行匹配矩阵规模，不裁剪快照。
- 本次差异功能通过 15 项相关测试、前端构建及桌面/390px 手机浏览器执行后验证，覆盖模式切换与无变更节点。
- UI 修订：移除业务内容中的重复导航与预览提示，复用宿主顶部栏和外侧留白；独立运行入口把优化问题归入“意图优化”。词库消除双边框搜索和套层卡片；优化列表采用标题、搜索、状态、操作与表格的紧凑结构；方案默认定位知识节点差异，保留人工选择和编辑。
- 本轮再次通过类型检查与完整构建。1440px 桌面和 390px 手机浏览器验证三条选词、确认后导航同步、列表、单条评估、方案、批量展开和手机弹窗；文档宽度未溢出，未捕获页面运行异常。原共享 vendor 文件未修改。
- 已运行冻结锁安装、类型检查、构建及模块测试。
- 浏览器验证了三问题选取、确认弹窗、小屏边界和中心命中、批量评估、展开矩阵、方案编辑、七项动作执行、刷新后读取执行记录和知识变更定位。
- 自动化验证资料待办不改善知识分、未经确认节点不算充分支撑、非首条问题精准执行、幂等请求、刷新恢复、撤销及后续修改冲突。
- 本轮没有运行数据库迁移、真实服务器 API、正式知识保存或供应商任务，也没有发布子域名、合回 Dashboard 或发布生产。

正式环境验收应执行新表迁移，检查两个项目的数据隔离、同时提交的版本冲突、断线后继续原执行、实际节点编辑/确认与撤销冲突，并确认 Dashboard 宿主导航配置。
