# 五列问题宇宙工作簿规范

## 可见结构

- 仅创建一张工作表：`问题列表`。
- 表头严格为：`序号 / 问题 / 核心词 / 核心词分类 / 问题细分`。
- `问题` 列表示用户可直接输入搜索框的搜索表达，允许无句末标点的搜索短语与以一个 `？` 结尾的完整问句混排。
- 工作表使用区域严格为 `A1:E161`。
- 不增加说明页、证据页、审计页、隐藏页、图表、公式、批注或数据验证。
- 不包含热度、创建日期、评分、来源或生成标记。

## 行顺序

1. 行业排名词：序号 1–20。
2. 竞品对比词：序号 21–40。
3. 美誉舆情词：序号 41–60。
4. 产品场景词：序号 61–160。

类内按核心业务相关性和用户决策价值排列，不创建或显示数值分数。

## 样式

复刻参考成品的简表样式并删除热度、日期两列：

- 表头行高 25，灰色 `#C0C0C0` 填充，宋体 14 号加粗，居中，自动换行，黑色细边框。
- 正文行高 18，Calibri 11 号，不换行，不填充，不额外加边框。
- 列宽：A=8、B=50、C=34、D=15、E=15。
- 保留网格线，不冻结窗格，不启用筛选。
- 不因某类不同而添加彩色分区。

## 构建工具

同时使用 Spreadsheets skill，并遵守它的依赖加载和验证流程：

1. 调用工作区依赖加载器获取 Node.js 和 `node_modules` 路径。
2. 在会话专属临时目录创建 `node_modules` 符号链接。
3. 把 `scripts/build_workbook.mjs` 复制到该临时目录后运行，确保 `@oai/artifact-tool` 从临时目录解析。
4. 在第一次实际创建工作簿命令前，按 Spreadsheets skill 要求运行一次 `mark_artifact_operation_started.mjs`。
5. 不使用 openpyxl、xlsxwriter、pandas.ExcelWriter 或系统全局 Node 包写入工作簿。

先验证 JSON：

```bash
python3 "<skill-dir>/scripts/validate_questions.py" <final.json>
```

再构建：

```bash
node <temp-run-dir>/build_workbook.mjs <final.json> <output.xlsx> --preview <temp-preview.png>
```

预览图仅用于视觉检查，不交付给用户。

## 验证

构建器必须完成：

- 检查输入恰好 160 行和五个字段；
- 写入并检查 `A1:E161`；
- 检查表头和四类分组；
- 扫描 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#N/A`；
- 渲染整张表；
- 导出后重新导入 `.xlsx`；
- 再次检查工作表名称、使用区域、行列数，并逐项比对全部 `A1:E161` 单元格；
- 清理构建器产生的 `.inspect.ndjson` 旁车文件，最终输出目录只保留 `.xlsx`。

人工查看预览，确认：

- 表头完整；
- 问题和核心词无明显截断；
- 没有空白工作表或多余区域；
- 160 行均可读。

输出到 `outputs/<unique_thread_id>/`，文件名为：

```text
<客户简称>-问题宇宙四分类精选-YYYYMMDD.xlsx
```

最终回复只引用一次该工作簿，不引用 JSON、构建器或预览图。
