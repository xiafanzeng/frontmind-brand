# 全景报告内容完整性与丰富度契约

本契约是 S10 最终组装报告的最高内容约束：**最终《AI智能品牌优化方案全景报告》必须吸收 S1-S9.8 面向客户的有效产物，并执行明确的客户版删项过滤。**报告可以重组语言，但不能用“详见附件/详见原文件”替代应保留的正文，也不能因为排版整理而删掉实质内容。

> 重要变更（字数门控已移除）：本工作流**不再设置任何最低字数、最少字符数、最少内容模块数或覆盖率百分比的硬性门控**。历史版本曾要求"客户正文不少于 36000 字符""内容模块不少于 24 个""每阶段来源不少于 2200–3200 字符""锚点覆盖率不低于 90%"等。这些硬性数字门会逼迫上游为凑字数而反复扩写、填充"补充详细分析与执行细则"等无意义的重复段落，因此一律取消。新的达标口径是：**只要 Wide Research 流程已执行完成，且各 S 阶段的真实内容已完整填入最终报告对应章节，即视为达标。**

## 1. 组装原则

1. 最终报告不是把 S1-S9.8 的文件名或源报告全文直接拼接，而是把核心判断、证据、获准展示的结构化表格和行动建议**完整承接**为客户可读的咨询正文。明确删除项与内部结构化输入不进入客户正文。
2. S1-S9.8 每个阶段都必须在 S10 HTML 中有可定位的客户正文承接（对应的 `source-stage-block` 必须存在且唯一）；S10 数据 JSON 必须记录对应来源与是否进入报告。
3. S11 只能做格式整理、合并空白、优化分页，不得删除已经通过 S10 客户版过滤的实质内容；如内容过多，应优化排版而不是删减。
4. 主报告不逐条堆叠所有原始 AI 平台回答；逐条原始回答保留在内部监控 JSON。主报告保留监控结论、平台差异、代表性证据、品牌缺口和行动含义（本工作流不生成《问题监控数据文件 PDF》）。
5. “危机与错误信息回应模板”“下游注入规则”“重校触发条件”属于客户版明确删除项，必须按来源标题层级整节过滤。保留的来源局部标题应去除源文档编号，最终 11 个正式分部编号保持不变。

## 2. 各阶段进入主报告的内容

| 阶段 | 必须进入《全景报告》的内容 |
|---|---|
| S1 品牌资产知识库 | 企业事实、业务/产品结构、官网与公开证据、可引用资产、资料冲突或不确定性 |
| S2 营销图谱 | 用户角色、使用/购买/决策场景、问题路径、搜索意图分层、内容承接逻辑 |
| S3 品类趋势 | 趋势、趋势证据、机会/风险、优先级评分和对品牌的影响 |
| S4 品牌定位 | 竞品/标杆、定位声明、价值三角、差异化矩阵、定位证据链（不展示竞品心智地图） |
| S5 品牌诊断 | S5.0 可信监控数据汇总、品牌可见性、竞品占位、Gap 诊断、根因与风险主题 |
| S5.5 语义资产 | 实体、属性、关系、覆盖缺口、语义资产评分、优先修复项 |
| S6 话语体系 | 核心话语 token、证据化表达、场景表达、禁用表达、可复用文案规则 |
| S7 视觉符号体系 | 视觉母题、识别元素、跨场景视觉规则、Prompt 体系、视觉风险边界 |
| S8 问答架构 | 12 周内容日历；问答树、问答矩阵和标准答案保留为内部输入 |
| S9 业务赋能 | 优先行动、负责人/协作方、依赖、里程碑、KPI、风险与 GEO 落地协作 |
| S9.8 标题钩子 | 紧随 12 周内容日历的同章小节，含主题/问题、内容类型、标题和用途 |

> 上表只描述"内容应当包含什么"，不再规定"必须达到多少条/多少字"。各阶段产出多少，就完整承接多少。

## 3. 不漏内容的结构性校验（保留，非字数门）

下列校验保证"各阶段内容真实、完整地进入报告"，本质是结构存在性与防造假，不是字数门：

1. S1、S2、S3、S4、S5、S5.5、S6、S7、S8、S9 的每个来源块必须且只能出现一次，且块内有实质内容（非空）。
2. S8 只要求 12 周内容日历完整渲染为客户可读模块；问答树和问答矩阵不得展开。
3. S9 行动必须进入“优先行动清单”。
4. S9.8 标题钩子已生成即应渲染，并紧随 12 周内容日历。
5. 差异化矩阵必须带 `data-differentiation-matrix` 标记并显示真实品牌/竞品值。
6. 不得出现中间产物残留、上游文件名或来源 `h1`、阶段输出头注、绝对路径、任务 ID、占位符、`None`、`待补齐`、`暂无` 或明确删除项。
7. 监控数据必须来自墨力指数 API 自动取数生成的真实 AI 问答监控表，且已自动确认；同时必须包含已确认并通过三层对账的独立信源表（引用分析表）数据。不得模拟或手工构造。

## 4. 防灌水与防占位（保留）

为避免"为凑字数而填充无意义重复内容"，以下防线保留：

- 同一源文件重复行比例超过 25%，视为质量失败，需返回对应阶段重写；
- 占位内容（"暂无""待补齐""示例"等）占比过高，视为空壳；
- 两个不同阶段正文高度雷同（跨阶段 Jaccard 相似度过高），必须返回对应阶段重写，不能以改标题方式通过检查。

## 5. 写作要求（建议，非门控）

建议每个主要章节尽量包含"结论 → 依据/证据 → 对品牌的影响 → 可执行动作"四层信息，使报告专业可读。但这是写作建议，不再以字数或模块数作为强制门控。仍应避免：只给泛化建议、只放图表不解释、只放清单不说明依据。

## 6. S10 输出的内部证明

`S10_{brand}_全景报告数据.json` 必须包含：

- `source_manifest`：实际读取了哪些 S 阶段文件；
- `source_quality_gate`：上游文件是否存在、非空、无占位、无重复灌水；
- `source_coverage_gate`：每个 S 阶段来源块是否存在且唯一、是否进入报告（仅记录实际覆盖率数值，不作为阻断阈值）；
- `report_richness_gate`：仅记录报告实际可见字数与模块数（`gate_enforced=false`，不阻断）；
- `template_compliance`：报告结构、禁用内容检查；
- `pdf_generation.cover_contract`：官方模板文件名/SHA、2 页 A4校验、HTML 官方封面预览替换、最终 PDF 首尾视觉指纹；
- `final_formatting`：S11 是否在不删内容、保留独立分隔页且强制拼接官方封面/封底的前提下完成排版整理。

结构性校验（来源块存在且唯一、无残留/占位、监控真实且已确认、S11 版面无真正空白页、固定封面模板与最终 PDF 首尾视觉指纹通过）任一失败，不能输出最终 PDF。字数/覆盖率/模块数不再作为阻断条件。

## 7. 章节分隔页

最终报告共 11 个正式分部。每个分部（如“报告范围与诊断口径”）的章节分隔页**必须单独占一整页**：页面只放分部编号、中英文标题与一句简述，其余留白，正文从下一页开始。“内容标题钩子”是第五部分内的小节，不生成独立分隔页。S11 在版面检测时会把独立分隔页排除出空白页/稀疏页判定。

- 模板必须恰好为 2 页 A4，SHA-256 必须为 `e37c51f793649fcf561c80d80b4b80ae1f70c470ec8a6956523b1795f369872d`。
- 客户 HTML 使用官方第 1 页的哈希命名安全预览替换旧 HTML 封面；HTML 不追加封底。
- S11 默认强制形成“官方封面 + 正文 + 官方封底”，禁止 `--no-cover-stitch`、`--keep-html-cover`、双封面和正文直出。
- 最终 PDF 第 1 页与最后 1 页必须在统一 DPI/A4 画布上分别匹配模板第 1/2 页视觉指纹；该门禁不可被打包调试参数跳过。
