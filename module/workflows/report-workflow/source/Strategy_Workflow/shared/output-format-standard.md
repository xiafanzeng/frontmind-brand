# FrontMind 输出格式标准 — 固定双问题全景报告版

## 1. 核心边界

本版在 S10 完成全景报告内容整合后，必须经过 S11 成品格式整理与版面复核；最终交付止于 S11 整理后的全景报告和问题监控数据，不生成执行层 strategy_pack，不进入 E0-E5。

## 2. 源文件优先

S1-S9.8 每个节点保留 JSON/Markdown 等源文件；S10 统一生成内容完整的 HTML/PDF，S11 在不改变战略结论的前提下完成紧凑排版、重新渲染与空白页复核。

## 4A. 标准产物文件名闭环

所有 S 阶段标准文件名以 `shared/全链路标准产物文件清单.md` 和 `shared/stage-output-registry.json` 为机器可读准绳。后续质量门、S10 渲染与最终打包均优先读取这些 canonical 文件名。

若执行过程中出现“文件命名与 completeness_checker 要求不一致”，必须运行 `output_contract_normalizer.py` 规范化，不得临时新写浅层替代文件；全量 `completeness_checker.py` 仅在 S9.8 完成后运行。

## 6. 口径铁律

1. Q1 `{核心产品}推荐` 可计入可见度、推荐率、排名。
2. Q2 `{品牌名}有什么缺点和问题？` 只进入舆情和风险分析，不计入排名。
3. 监控数据必须来自墨力指数 API 自动取数生成的真实 AI 问答监控表；信源引用分析必须来自 API 自动生成的真实信源表（引用分析表）。
4. 任一表格缺失、解析失败、记录不完整或引用三层无法对账时必须如实报告，不得用假数据补齐。
5. 低置信度事实必须标注待核实。
6. S5.0 必须同时导入 AI 问答监控表和信源表（引用分析表），两份 `.xlsx` 缺一不可。
7. 独立引用分析只进入 S5.5 语义资产审计下半部分，不在 AI 可见性章节重复铺陈。


## 本工作流 S10 模板约束

- `S10_{brand}_AI智能品牌优化方案全景报告.html/.pdf` 使用 `S10.../templates/panorama_report_template.html`，采用咨询级报告模板，突出经营层摘要、S3 市场趋势、S4 品牌定位、市场建议和 90 天 GEO 行动路线图；禁止使用脚本内联极简报告模板。
- 本工作流不生成《问题监控数据文件》客户版 HTML/PDF；监控数据仅保留内部 JSON（`S5_{brand}_frontmind_monitoring_data.json` / raw），逐条答案的诊断结论与代表性证据由 S5 报告和 S10 主报告承载。


## 本工作流 确认规则与模板强校验（融合版）

- 暂停点 1（唯一暂停点）：S4.8 生成固定双问题后，**AI 必须使用 `message(type="ask")` 发送确认单并阻塞等待用户回复**。用户确认问题文本后，才能执行 S5.0 API 自动取数导入（平台默认国内三平台）。
- S5.0 无数据确认暂停点：AI 问答监控表与信源表（引用分析表）双表导入、引用三层对账通过后自动写入 `data_confirmation_status=confirmed`，随后直接连跑 S5-S11 直至最终报告；不再生成《问题监控数据文件》，也不发送数据确认单。
- 进入客户可见产物的监控证据只允许：记录编号、平台、问题、提问次数、答案原文、答案实际引用（`citationList`）、检索参考来源（`referenceList`）；两类来源不得合并或相互替代。不得出现截图页、原始工作表行、上传路径或解析日志等导入内部信息。
- S10 全景报告必须使用 `panorama_report_template.html` 并强制检查模板结构；S5.0 监控数据未确认（非 confirmed）时不得生成最终报告。
- 客户 HTML 必须以官方封面第 1 页的安全相对路径预览替换旧 HTML 渐变封面；旧封面不得继续客户可见。HTML 不追加封底，封底由 PDF 组装唯一追加。
- S10 内容整合完成后必须执行 S11；S11 保留每个分部的独立整页分隔页（不压缩、不与正文合并），取消正文普通页面的强制分页，允许长卡片跨页，并对空白页与稀疏页进行独立检测（独立整页分隔页被自动豁免）。S11 未显式传 `--cover-pdf` 也必须自动使用固定官方模板。
- 生产交付禁止 `--no-cover-stitch` 和 `--keep-html-cover`。最终 PDF 第 1 页与最后 1 页必须分别匹配官方模板第 1/2 页视觉指纹；`no external cover`、双封面或缺封底均不得放行。
- 最终客户 HTML/PDF 必须整节过滤“危机与错误信息回应模板”“下游注入规则”“重校触发条件”，并去除来源局部标题编号；最终报告正式分部编号保持不变。
- 最终打包前必须运行 S10 模板/覆盖检查、S11 格式整理与版面复核；`final_delivery_packer.py` 仅在三道质量门全部通过后创建 ZIP。
