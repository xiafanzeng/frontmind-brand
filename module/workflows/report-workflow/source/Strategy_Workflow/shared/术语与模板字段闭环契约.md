# 术语与模板字段闭环契约

本文件解决另一类常见断点：上游 S 阶段使用了一个分析术语，但 S10 模板没有同名章节，执行 Agent 就临时说“发现某字段在模板中未出现，已替换为某字段”。这类临时替换会造成语义不稳定、覆盖率误判或内容被清洗器误删。

## 最高规则

1. **不能临时自创字段替换。** 如果 S 阶段术语与模板章节名不一致，必须先查本文件的“标准术语映射表”。
2. **术语规范化不得删除内容。** 旧术语只改标题或字段名，正文、表格、证据和行动建议必须完整保留。
3. **S10 负责统一客户可读术语。** 上游可保留研究型术语；进入最终《AI智能品牌优化方案全景报告》前，S10 渲染脚本会统一替换为客户版术语。
4. **出现未列入映射表的新术语时，不能跳过内容。** 正确做法是把该内容归入最接近的现有报告章节，并在 S10 数据 JSON 的 `terminology_normalization` 中记录映射；不得把内容删掉或改写成空摘要。
5. **来源局部标题编号不是客户版章节编号。** 进入 `.source-stage-block` 后，须去除 `11.`、`3.2`、`一、`、`（一）` 等源文档前缀，再按客户版标题渲染；不得修改最终“第一部分”至“第十一部分”。
6. **明确删除项不做术语映射。** “危机与错误信息回应模板”“下游注入规则”“重校触发条件”必须按标题层级整节过滤，不能改名后继续注入客户正文。

## 客户版标题规范化顺序

1. 先按来源 Markdown 标题层级识别并整节删除明确禁用章节；
2. 再剥离保留标题的源文档局部编号；
3. 最后执行标准术语映射；
4. 官方封面、目录和最终 11 个正式分部标题不参与局部编号剥离。

## 执行 Agent 遇到术语不匹配时的正确回复

不要说：

```text
发现“信源生态”在模板中未出现，已将相关内容替换为“品牌信源覆盖”，完成调整准备下一步。
```

应当说：

```text
已按《术语与模板字段闭环契约》完成术语规范化：上游“信源生态”映射为最终报告中的“品牌信源覆盖”。本次仅规范章节/字段名称，相关正文、表格、证据和行动建议继续保留并进入 S10 来源覆盖检查。
```

## 与文件名闭环的关系

- `全链路标准产物文件清单.md` 管文件名。
- `术语与模板字段闭环契约.md` 管章节名、字段名和客户版表达。
- 两者都必须在 S0.0 Workflow 阅读确认中被读取。
