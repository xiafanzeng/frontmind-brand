# FrontMind 本工作流 源文件深度与全景报告覆盖契约

本契约解决两个生产问题：上游阶段文件“有文件但没内容”，以及 S10 “读取了文件却没有真正进入客户报告”。它对 S1-S9.8、S10 和最终打包均为强制约束。S10 还必须遵守 `全景报告内容完整性与丰富度契约.md`，保证客户报告足够丰富且不遗漏各阶段核心内容。

## 1. 上游内容存在性底线（字数门已取消）

> 重要变更：本工作流**不再对任何阶段设置最低字数 / 最低条数的硬性门控**。历史版本曾要求各阶段达到 2200–3200 字符、S9.8 至少 12 条等，这些字数/数量门会逼迫上游为凑数而灌水、填充重复内容，现已全部取消。现在的达标口径是：**只要 Wide Research 已执行、各阶段产生了真实、非空、非占位、非重复灌水的实质内容即可。**

“有效正文”指去除标题、表格分隔线、模板占位、重复行和纯品牌名后的中文/英文实质内容。下表只描述“每个阶段应具备哪些分析结构”，**不再规定字数**；只要该阶段内容非空且含基本章节结构即可。

| 阶段 | 必须具备的分析结构（不再设字数门） |
|---|---|
| S1 品牌事实 | 企业/品牌事实、产品与业务、公开证据、事实冲突或不确定性、可引用资产 |
| S2 用户意图 | 受众、任务/场景、意图分层、问题路径、决策阻力、内容承接 |
| S3 市场趋势 | 趋势、评分依据、证据、机会/风险、优先级判断 |
| S4 品牌定位 | 竞品、心智空位、定位声明、价值三角、差异化证据、边界 |
| S5 品牌诊断 | 监控事实、平台差异、可见性缺口、竞品占位、风险主题、根因 |
| S5.5 语义资产 | 实体、属性、关系、覆盖度、缺口、优先修复项 |
| S6 话语体系 | 核心话语 token、证据化表达、禁用表达、场景示例、应用规则 |
| S7 视觉体系 | 视觉母题、识别元素、跨场景规则、Prompt 体系、风险边界 |
| S8 问答架构 | 问答树、问答矩阵、优先级、标准答案要点、内容形态、目标平台 |
| S9 业务赋能 | 行动项、负责人、依赖、里程碑、KPI、风险、90 天节奏 |
| S9.8 标题钩子 | 标题钩子，含问题/主题、内容类型、标题、用途或预期效果 |

## 2. 结构化 JSON 底线

JSON 不能仅“可解析”。每个文件还必须满足：

- 非空叶子节点数量达到阶段阈值；
- 核心数组不是空数组，且不以同一条内容重复填充；
- 不得以 `暂无`、`待补齐`、`TODO`、`示例` 等占位值构成主体；
- 同一阶段 JSON 与 Markdown 必须在品牌、核心产品、关键结论上保持一致；
- 监控数据必须来自墨力指数 API 自动取数生成的真实表格，绝不允许模拟或手工构造。

## 3. 禁止“重复内容抬高字数”

- 同一文件重复行比例超过 25%，视为质量失败；
- 同一源文件被多个通配模式重复读入时，只计一次；
- 两个不同阶段正文高度雷同，必须返回对应阶段重写，不能以改标题方式通过检查。


## 3A. 文件名与内容深度分离

文件名不一致不是内容缺失。若某阶段已有足量 JSON/Markdown，只是命名与标准不一致，必须先运行 `output_contract_normalizer.py` 复制为标准文件名；不得为了补文件名而重写一个浅层摘要。

内容深度不足才返回对应 S 阶段补写。全量 `completeness_checker.py` 只在 S9.8 完成后运行，避免在 S5 前错误要求补齐尚未执行的后续阶段文件。

## 4. S10 真正嵌入规则

S10 必须建立内部 `source_manifest` 和 `source_coverage_gate`，并写入 `S10_{brand}_全景报告数据.json`：

1. 列出 S1-S9.8 实际读取的文件路径、大小、SHA-256；
2. 为每个正文阶段生成同名 `source-stage-block`，保证该阶段内容真实进入报告（仅记录实际覆盖率数值，**不再作为百分比阈值阈断**）；
3. S1、S2、S3、S4、S5、S5.5、S6、S7、S8、S9 的来源块必须存在且唯一、块内非空；
4. S5 诊断正文必须有独立客户页面；
5. S8 问答树和问答矩阵保留为内部输入，不在客户正文展开；内容日历已生成即应完整渲染；
6. S9 行动建议必须进入“优先行动清单”；
7. S9.8 标题钩子已生成即应紧随 12 周内容日历进入同章小节（不再硬性要求 12 条）；
8. 任一阶段缺失、来源块为空或只出现标题时，S10 必须阻断；但**不再因字数/覆盖率不足而阻断**。

覆盖信息仅写入内部 JSON 与质量报告，不在客户正文展示 S1-S9 文件名。

9. S10 默认采用“客户有效内容完整组装模式”：获准进入客户正文的阶段内容不得只转为短摘要；明确删除项和内部结构化输入不得直接拼入。
10. S6/S7 来源中以“危机与错误信息回应模板”“下游注入规则”“重校触发条件”为标题的章节必须按标题层级整节删除，不得残留正文。
11. `.source-stage-block` 内所有保留标题必须剥离源文档局部编号（如 `11.`、`3.2`、`一、`、`（一）`）；不得处理最终报告的正式分部编号。

## 5. 客户报告深度原则

- 不以“每阶段一段摘要”代替分析；建议每个主要章节尽量包含判断、依据、影响和行动四层信息（这是写作建议，**不再以字数/模块数作为强制门控**）；
- 先给结论，再给证据和推导，最后给动作；
- 结构化图表与完整解释必须同时存在，禁止只有图表没有解释；
- 原始监控逐条答案保留在内部监控 JSON，主报告保留汇总结论、平台差异和代表性证据（本工作流不生成《问题监控数据文件》）；
- 删除内部工作流痕迹、来源 `h1`、阶段输出头注和本地绝对路径，但不能以清洗为由删掉获准展示的实质分析；
- 客户报告不得展示问答树问题清单、问题承接矩阵、质量与风险闸门、句式模板、危机与错误信息回应模板、下游注入规则、重校触发条件、趋势机会坐标图或竞品心智地图；
- 差异化矩阵必须由真实 S4 数据渲染，并带 `data-differentiation-matrix` 标记。

## 6. 最终格式整理

S10 生成内容后必须进入 S11：

- 固定官方封面文件为 `S10.AI智能品牌优化方案全景报告生成师.skill/templates/frontmind_cover_front_back.pdf`，必须恰好 2 页 A4，SHA-256=`e37c51f793649fcf561c80d80b4b80ae1f70c470ec8a6956523b1795f369872d`；
- 客户 HTML 必须用官方第 1 页安全预览替换旧 HTML 封面；生产执行禁止 `--no-cover-stitch` 和 `--keep-html-cover`；
- **每个分部的章节分隔页必须独立占一整页**，正文从下一页开始；分隔页不压缩、不优化，不得被合并为正文页首的一行小标题；
- 取消正文 `report-page` 的机械强制分页；仅封面、目录、经营层摘要和分隔页保留强制分页；
- 对过长卡片允许跨页，对图表和短卡片保留整体性；
- 自动清理空段落、孤立标题和纯装饰空白；
- 渲染后检测空白页与稀疏页；独立整页分隔页会被自动豁免，不因其留白而判不合格；存在真正的空白页才不得打包；
- 最终 PDF 第 1 页与最后 1 页必须分别通过与官方模板第 1/2 页的固定画布视觉指纹比对；S11 未显式传封面路径也必须自动使用固定模板，任何降级为正文直出均须阻断。
