# FrontMind 核心执行原则契约 本工作流

本契约把原先分散在各阶段质量门里的要求提炼为两个最高原则，供 外部 Agent 在执行前、执行中、执行后反复校验。

## 核心原则 1：先读流程和暂停点逻辑

Workflow 不是参考材料，而是执行规程。任何 Agent 在收到企业名称后，不能直接研究并生成报告，必须先完成：

1. 读取根目录最高原则、主 SKILL、Master Control、S0 和共享契约；
2. 识别唯一的暂停点和 S5.0 自动确认规则；
3. 生成 S0.0 workflow reading manifest；
4. 明确第一轮最多执行到暂停点 1。

暂停点为硬中断，且本工作流只有一个：

- 暂停点 1：S4.8 固定双问题生成后，等待用户确认问题（数据来源固定为 API 自动取数，平台默认国内三平台）。
- S5.0 无数据确认暂停点：API 自动取数生成的两份表格（AI 问答监控表 + 信源表/引用分析表）导入、引用三层对账通过后自动确认（`data_confirmation_status=confirmed`），直接连跑 S5-S11 直至最终报告。

任何“先全部做完，再交付 PDF”的行为都不合规。

## 核心原则 2：每个研究型 S 阶段都必须调用 Wide Research

Wide Research 必须按 S 阶段独立调用和落盘，不能只做一次“并行研究”。

强制阶段：S1、S2、S3、S4、S5、S5.5、S6、S7、S8、S9、S9.8。

每个阶段必须同时满足：

1. 使用 Wide Research；
2. 输出该阶段规定的 Markdown / JSON；
3. 写入 `_execution/{stage_id}_{brand_id}_wide_research_manifest.json`；
4. manifest 里有 `used_wide_research=true`、检索问题、外部来源、生成文件和状态；
5. 不得用聊天总结代替文件。

## S5.0 例外：数据只能通过 API 自动取数生成两份表格

S5.0 不属于 Wide Research 阶段。它只能通过墨力指数 API 自动取数生成两份 `.xlsx`（AI 问答监控表 + 信源表/引用分析表）并自动导入（路径B手动上传已于 v3 移除；平台默认国内三平台，仅项目输入明确指定时覆盖）。取数脚本自动调用两个导入脚本，并通过引用数据三层对账；任一环节失败时停止并保留真实错误，不得模拟、手工构造或用 Wide Research 替代。

## Agent 执行自检句

每轮输出前，Agent 必须自检：

```text
我是否已经越过了未确认的暂停点？
我是否把 Wide Research 合并成了一次泛研究？
我是否使用 API 自动取数生成的两份 S5.0 表格而不是模拟数据？
我是否为当前阶段写入了文件和 manifest？
```

任一答案为“否/不确定”，必须停止并修复，不得继续生成最终报告。


## 术语与模板字段闭环

所有上游研究术语进入最终报告前，必须按 `Strategy_Workflow/shared/术语与模板字段闭环契约.md` 统一成客户版术语。术语规范化不得删除阶段内容。
