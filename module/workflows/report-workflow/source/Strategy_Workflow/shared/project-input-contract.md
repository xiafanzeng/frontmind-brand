# 项目输入与通用复用契约 — 本工作流

本契约确保 FrontMind Workflow 可以长期复用到不同企业，而不是绑定某一个客户案例。本工作流 进一步明确：**除企业名称外，其余项均可缺失；缺失项必须由 Wide Research 有证据地补全，不能凭模型猜测。**

## 1. 输入字段

每次执行只允许从用户输入区读取本次项目变量。支持完整输入，也支持最小输入。

### 1.1 最小输入

```text
企业名称：{brand_name}
用户备注：{user_notes_or_none}
报告语言：中文
```

### 1.2 完整输入

```text
企业名称：{brand_name}
官方网站：{official_site_or_未提供待调研}
所在行业/品类：{industry_or_category_or_未提供待调研}
核心产品/服务：{main_product_or_service_or_未提供待调研}
目标市场/地区：{target_market_or_未提供待调研}
竞争对手：{competitors_or_未提供待调研}
用户备注：{user_notes_or_none}
报告语言：中文
```

Workflow 内不得保留任何固定客户名称、网址、竞品或行业判断。任何示例都必须使用 `{brand_name}`、`{brand_id}`、`{competitors}` 等变量表示。

## 2. 字段必填级别

| 字段 | 级别 | 处理规则 |
| --- | --- | --- |
| 企业名称 / brand_name | 必填 | 缺失则暂停询问；不可用占位符启动流程。 |
| 官方网站 | 可选 | 缺失时由 S1 Wide Research 识别候选官网并标注置信度。 |
| 所在行业/品类 | 可选 | 缺失时由 S1/S3 根据主营业务和资料来源推断。 |
| 核心产品/服务 | 可选 | 缺失时由 S1/S4 推断；进入 S4.8 前必须明确供固定问题 Q1 使用。 |
| 目标市场/地区 | 可选 | 缺失时由 S1/S3 根据经营区域、官网、财报、新闻和业务范围推断。 |
| 竞争对手 | 可选 | 缺失时由 S4 识别 3-5 个高相关竞品、标杆或替代方案。 |
| 用户备注 | 可选 | 为空时不阻断；非空时必须进入 S4、S5、S8、S9、S10。 |
| 报告语言 | 可选 | 默认中文。 |

## 3. 缺失值识别

以下内容均视为“缺失但允许继续研究补全”：

```text
空白、未知、未提供、待调研、N/A、NA、None、null、无、不清楚、暂缺、留空、待补充、{...占位符...}
```

缺失值不得直接进入最终客户版 PDF。若某项在研究后仍无法确认，必须在阶段文件中说明“不确定原因、已检索来源、候选项和建议用户确认的问题”，并在必要时暂停。

## 4. 变量生成

- `brand_name`：报告正文展示名，来自用户输入。
- `brand_id`：文件与脚本安全名，由 `brand_name` 转换而来，只允许中文、英文、数字、下划线和短横线。
- `company_name`：渲染器展示名称，通常等于 `brand_name`。
- `main_product`：固定监控问题 Q1 的核心对象。若用户未给出，S1/S4 必须基于资料推断并说明依据。
- `competitors`：若用户给出，必须全链路使用；若用户未给出，S4 必须基于 Wide Research 识别 3-5 个高相关竞品、标杆或替代方案。
- `competitor_source_type`：竞争对手来源标记。用户指定为 `user_provided`；Workflow 研究识别为 `workflow_researched`。

## 5. S0.1 输入解析与补全计划

进入 S1 前必须先执行 S0.1，输出项目输入解析与补全计划。

### 5.1 原始输入落盘

```text
outputs/{brand_id}/00_project_input/project_input_raw.txt
```

### 5.2 推荐脚本

```bash
python3 Strategy_Workflow/S0.策略编排师.skill/scripts/project_input_resolver.py \
  --input "outputs/{brand_id}/00_project_input/project_input_raw.txt" \
  --output-root "outputs"
```

### 5.3 必须输出

```text
outputs/{brand_id}/00_project_input/S0.1_{brand_id}_输入解析与补全计划.json
outputs/{brand_id}/00_project_input/S0.1_{brand_id}_输入解析与补全计划.md
outputs/{brand_id}/_execution/S0.1_{brand_id}_input_resolution_manifest.json
```

S0.1 文件必须包含：

- `brand_name`、`brand_id`；
- 已知输入字段；
- 缺失字段清单；
- 每个缺失字段分配到哪个阶段补全；
- 需要 Wide Research 的检索方向；
- 是否存在同名企业、官网冲突、行业歧义等需要暂停确认的问题。

## 6. 缺失信息补全规则

### 6.1 官方网站未知

S1 使用 Wide Research 识别候选官网，至少交叉查看：搜索结果、企业介绍页、官方社媒/公告、权威商业数据库、新闻或监管/交易所资料。若出现多个高相似候选，必须暂停确认，不得任意选择。

### 6.2 行业/品类未知

S1/S3 根据主营业务、收入来源、产品/服务描述、用户备注和市场资料推断，并写明“一级行业、细分品类、AI 搜索场景分类”。

### 6.3 核心产品/服务未知

S1/S4 必须推断一个适合进入固定监控问题 Q1 的核心对象。进入暂停点 1 时，必须把该对象展示给用户确认。例如：

```text
Q1：{核心产品/服务}推荐
Q2：{品牌名}有什么缺点和问题？
```

### 6.4 竞品未知

S4 必须识别 3-5 个高相关竞品、标杆或替代方案，说明入选理由，并标注 `workflow_researched`。若用户备注中提到“对标某品牌”“超越某品牌”等表达，该品牌必须纳入竞品或标杆集合。

### 6.5 用户备注为空

不阻断流程。默认战略目标为：

- 提升 AI 搜索可见性；
- 强化品牌语义资产与可引用内容；
- 建立问答矩阵与内容日历；
- 形成 90 天 GEO / AI 品牌优化行动路线。

## 7. 不可写死规则

以下内容不得写死在 Workflow 中：

- 企业名、品牌名、网址；
- 竞品或行业名称；
- 固定报告结论；
- 固定业务痛点；
- 固定行动路线；
- 固定监控结果。

允许写死的只有流程规则、文件规范、质量门、双表导入方式、暂停点和安全禁令。
