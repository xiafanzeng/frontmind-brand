# 全链路标准产物文件清单

本文件解决一个常见断点：阶段已经完成了 Wide Research，但文件名与后续 `completeness_checker`、S10 渲染器、最终打包器不一致，导致 Agent 在中途临时“补齐文件名”。

## 最高规则

1. **文件命名是流程闭环的一部分。** 每个 S 阶段必须优先输出下面的标准文件名；不能自创文件名后留给后续阶段猜测。
2. **文件名不一致时只能规范化，不能重写浅层替代文件。** 如果已有等价内容，运行 `output_contract_normalizer.py` 复制为标准文件名；如果内容本身不够深，才回到对应 S 阶段补写。
3. **`completeness_checker.py` 只能在 S9.8 完成后运行。** S1-S4 或 S5 前的命名检查应运行 `output_contract_normalizer.py --stages ...`，不要提前运行全量完整性检查。
4. **每个 Wide Research manifest 的 `generated_files` 必须包含本阶段标准产物路径。** 可以额外列出别名文件，但标准文件必须存在。
5. **官方封面资产属于 Workflow 固定输入，不是项目可选文件。** `S10.../templates/frontmind_cover_front_back.pdf` 必须恰好 2 页 A4，SHA-256=`e37c51f793649fcf561c80d80b4b80ae1f70c470ec8a6956523b1795f369872d`；不得用项目目录中的同名文件覆盖。

## 推荐命令

第一轮进入暂停点 1 前，统一规范 S1-S4 文件名：

```bash
python3 Strategy_Workflow/S0.策略编排师.skill/scripts/output_contract_normalizer.py \
  --brand "{brand_id}" \
  --workspace "outputs/{brand_id}" \
  --stages S1,S2,S3,S4 \
  --strict
```

第三轮进入 `stage_execution_checker` 与 `completeness_checker` 前，统一规范 S1-S9.8 文件名：

```bash
python3 Strategy_Workflow/S0.策略编排师.skill/scripts/output_contract_normalizer.py \
  --brand "{brand_id}" \
  --workspace "outputs/{brand_id}" \
  --stages S1,S2,S3,S4,S5,S5.5,S6,S7,S8,S9,S9.8 \
  --strict
```

## 与最终报告的关系

- S10 只从标准产物清单和可验证别名中读取内容，生成 `source_manifest` 和 `source_coverage_gate`。
- 《AI智能品牌优化方案全景报告 PDF》必须充分吸收 S1-S9.8 的核心内容；命名规范化只是为了保证读取链路稳定，不得成为删减内容的理由。
- 监控数据 JSON 只能由墨力指数 API 自动取数生成的 AI 问答监控表导入产生（molizhishu_api 唯一路径），不能用 Wide Research 或手写数据替代；本工作流不再生成《问题监控数据文件 PDF》。
- 最终主报告不是“存在一个 PDF”即可：必须使用固定官方两页模板，客户 HTML 已替换旧封面预览，且最终 PDF 首尾视觉指纹通过；禁止 `--no-cover-stitch`、`--keep-html-cover` 和 `no external cover`。
