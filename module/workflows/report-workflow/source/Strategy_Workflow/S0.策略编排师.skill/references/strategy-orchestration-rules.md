# Strategy Orchestration Rules — 本工作流 页级模板强化版

## 1. 执行顺序

```text
S1 → S2 → S3 → S4 → S4.8 → [暂停点1] → S5.0（双表导入自动确认，无数据确认暂停点）→ S5 → S5.5 → S6 → S7 → S8 → S9 → S9.8 → S10 → template_compliance_check → final_delivery_pack
```

## 2. 固定双问题

1. `{核心产品}推荐`：进入推荐可见度、品牌提及、竞品占位和排名分析。
2. `{品牌名}有什么缺点和问题？`：只进入舆情风险、信任边界和回应建议。

## 3. S5.0 问题监控数据来源

监控口径：实际平台数 × 2 个固定问题 × 5 次动态计算；平台不设白名单，由上传的 AI 问答监控表 sheet 指定。

S5.0 必须在暂停点 1 用户确认固定双问题后运行墨力指数 API 自动取数（v3 唯一路径，平台默认国内三平台 doubao/yuanbao/qianwen，仅项目输入明确指定时覆盖）：

- 执行 `fetch_molizhishu_monitoring.py`：自动提交 2 问 × 平台 × 5 次任务、轮询、生成两份契约 `.xlsx`。
- 自动调用 `import_monitoring_spreadsheet.py` 与 `import_citation_analysis_spreadsheet.py`（`--data-source molizhishu_api`）完成导入与自动确认；全程无需上传任何文件。
- 两份表格格式分别遵守 `uploaded-monitoring-spreadsheet-contract.md` 与 `uploaded-citation-analysis-spreadsheet-contract.md`（作为格式契约）；信源引用分析必须通过媒体层、内容层、问题明细层三层对账。

**最高优先级禁令**：绝对禁止模拟/伪造/构造监控数据。脚本失败时向用户报告错误，绝不编造数据代替，尤其不得“模拟 AI 平台对两个固定问题的回答数据”。

## 4. 暂停闸门

- 暂停点 1（唯一暂停点）：固定问题确认后，方可执行 S5.0 API 自动取数（平台默认国内三平台）。
- S5.0 无数据确认暂停点：AI 问答监控表与信源表（引用分析表）两份数据均导入、引用三层对账通过后自动确认（`data_confirmation_status=confirmed`），直接进入 S5 及后续，直至最终全景报告交付。

## 5. S10 报告模板铁律

### 5.1 客户版禁止内容

| 禁止类型 | 示例 |
|---|---|
| 节点编号/文件名 | S1、S3、S9.8、S1_brand.json |
| 上游头部元信息 | 框架版本、生成时间、生成日期、数据来源 |
| 内部提示 | 报告节选、工作流证据地图、交接至 |
| 模板残留 | None、待补齐、待确认、暂无 |
| 内部字段 | taskId、subTaskId、reasoningProcess、COT_START/COT_END |
| 截图索引表 | “截图 有”“各平台提问有截图” |

### 5.2 图表优先

S10 主报告必须用真实数据呈现：AI 平台表现、推荐题品牌提及率、竞品占位、差异化矩阵和 AI 语义资产五维评分，并在 AI 语义资产审计下半部分呈现 Top 信源条形图、高频问题及代表性信源/内容表格。三层对账/集中度 KPI 与模型引用量不进入客户报告。趋势机会坐标图和竞品心智地图不进入客户报告。详细答案只放附件。

### 5.3 空白页防治

- 大表允许跨页，不得全局禁止分页。
- 卡片和图表防断页。
- 标题后必须跟实质内容，不允许标题独占一页。
- 渲染后必须通过合规检查。

## 6. 不进入执行层

不得调用 E0-E5，不生成正文、视觉执行资产或分发矩阵。
