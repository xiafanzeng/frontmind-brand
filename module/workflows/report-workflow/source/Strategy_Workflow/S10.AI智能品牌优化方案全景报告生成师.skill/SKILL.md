# S10 AI智能品牌优化方案全景报告生成师 — 本工作流

## 一、定位

S10 是客户版咨询报告整合器，不是文件拼接器，也不是摘要器。它可以重组和改写上游内容，但不得遗漏阶段核心分析。报告页数应随内容自然形成，不设置固定页数、字数门控或模块数目标。每个分部的章节分隔页独立占一整页，正文从下一页开始。

**客户版完整组装要求：**除经营层摘要外，主体章节必须完整承载面向客户的有效判断与依据。允许语言重写、排版重组和客户版删项过滤，但不得用“摘要”“概览”“详见附件”替代应保留的内容；内容日历、差异化矩阵、语义/话语/视觉资产、行动项和标题钩子不得遗漏。

## 二、强制输入

| 阶段 | Markdown | 结构化数据 |
|---|---|---|
| S1 | 品牌知识库 | 品牌事实图谱 |
| S2 | 营销图谱报告 | 营销图谱 |
| S3 | 品类趋势报告 | 趋势打分卡 |
| S4 | 定位分析报告/定位声明 | 定位声明 JSON |
| S5 | 品牌诊断数据 MD + Gap 报告 | 品牌诊断数据 JSON + 真实监控数据 |
| S5.0 API 取数 | 问答监控表导入摘要 + 信源/引用分析表导入摘要 | 真实监控数据 + `S5_{brand}_引用分析数据.json`；两份表格均由 API 自动生成、导入并自动确认 |
| S5.5 | 语义资产审计报告 | 语义资产评分卡 |
| S6 | 话语手册 | 话语 Token |
| S7 | 视觉符号体系报告 | 视觉 Prompt 包 |
| S8 | 问答报告（仅作内部输入） | 问答树、问答矩阵、内容日历；客户正文只展开 12 周内容编排 |
| S9 | 业务赋能建议包 | 从建议包提取推荐行动 |
| S9.8 | 可选说明 | 至少 12 条标题钩子 JSON |
| 官方成品封面 | `templates/frontmind_cover_front_back.pdf` | 恰好 2 页 A4；SHA-256=`e37c51f793649fcf561c80d80b4b80ae1f70c470ec8a6956523b1795f369872d` |

上游必须先通过 `shared/source-depth-and-coverage-contract.md` 和 `completeness_checker.py`。

## 三、本工作流 内容嵌入规则

1. 每个 S1-S9 来源阶段必须在 HTML 中生成独立 `source-stage-block`。
2. S5 品牌诊断必须有独立客户版模块；不能只加载却不渲染。
3. S8 的问答树、问答矩阵继续作为内部结构化输入，但客户正文不展开问题清单或问题承接矩阵；只完整渲染 12 周内容编排。
4. S9 推荐行动必须进入“优先行动清单”和行动设计正文，并由第十一部分 GEO 业务流程承接落地协作。
5. S9.8 有效标题钩子必须作为“12 周内容编排”后的同章小节进入标题表，不得另设独立章节或分隔页。
6. 同一物理文件即使被精确路径和通配符同时命中，也只能加载一次。
7. `.source-stage-block` 内不得保留上游 Markdown 的 `h1` 一级报告标题、版本/日期/输入/原则/数据源头注或本地绝对路径；来源正文直接承接客户版章节标题。
8. 图表必须先于同主题明细表，且只由真实上游数据生成：S4 差异化矩阵、S5 AI 可见性图、S5.5 五维达成度条形图均应在有数据时渲染。趋势机会坐标图与竞品心智地图不进入客户报告。
9. 必须把已确认的独立信源/引用分析表渲染为“品牌信源覆盖与引用结构”，放在语义资产审计下半部分；包含 Top 信源条形图、高频问题及代表性信源/内容表格。三层对账与集中度仅作为后台质量门，不在客户版展示；不得渲染模型引用量图表。
10. S6/S7 来源进入客户版前必须整节过滤标题为“危机与错误信息回应模板”“下游注入规则”“重校触发条件”的内容；不得只删标题而留下该节正文。
11. 所有保留的来源局部标题须剥离源文档编号，例如 `11.`、`3.2`、`一、`、`（一）`；只处理 `.source-stage-block` 内的来源标题，不得修改最终报告“第一部分”至“第十一部分”的正式编号。


## 三点五、内容丰富度与不漏阶段原则

S10 必须遵守 `Strategy_Workflow/shared/全景报告内容完整性与丰富度契约.md`：

1. S1-S9.8 的客户有效内容必须进入最终《AI智能品牌优化方案全景报告》；上游完整文件保留在交付包和内部结构化输入中，不等于全文直接拼入客户正文。
2. 每个主要章节必须包含“结论 → 依据/证据 → 对品牌的影响 → 可执行动作”四层信息。
3. **字数/覆盖率/模块数门控均已取消**：不再要求来源块覆盖率达 90%、正文达 36000 字符或模块达 24 个；只要各阶段来源块存在且内容已真实进入报告即可。
4. S11 只能整理版式和空白，不能删减 S10 已嵌入的阶段内容。
5. 监控明细 JSON 仅内部使用；主报告承载监控结论、平台差异、代表性证据和行动建议（本工作流不再生成《问题监控数据文件》PDF）。

## 四、来源证明

`S10_{brand}_全景报告数据.json` 必须包含：

- `source_files`：实际读取路径；
- `source_manifest`：每个文件的阶段、角色、路径、大小和 SHA-256；
- `source_quality_gate`：上游正文与结构化数据质量；
- `source_coverage_gate`：每阶段锚点数量、匹配数量和加权覆盖率；
- `template_compliance`：客户报告结构和内部字段检查。

各阶段来源块必须存在且唯一、块内非空；覆盖率仅作为记录写入内部 JSON，**不再作为百分比阈值阻断**。S8 只要求内容日历进入客户报告；问题树和问题矩阵保留为内部输入。差异化矩阵必须带 `data-differentiation-matrix` 真实渲染标记。仅在阶段缺失、来源块为空、矩阵无真实数据或出现中间产物残留/造假时返回非零并阻断 PDF。

## 五、客户报告结构

```text
官方封面 → 目录 → 经营层摘要
→ 报告范围与诊断口径（含 S1）
→ 市场趋势与品类机会（S3）
→ 品牌定位与竞争战略（S4）
→ 用户意图与问题路径（S2）
→ 问答架构与内容承接（S8：12 周内容编排；其后紧接内容标题钩子小节）
→ AI 可见性诊断 + 品牌诊断与 Gap（S5）
→ 语义资产审计（S5.5；下半部分加入独立信源/引用分析）
→ 话语资产与视觉资产（S6/S7）
→ 风险管理
→ 第十部分 GEO 战略选择（S9）
→ 第十一部分 GEO 业务流程
→ 官方封底
```

客户 HTML 的第一页预览必须由官方封面 PDF 第 1 页安全栅格化生成，并通过内容哈希文件名放入报告 `assets/`；旧 `.cover-page` 渐变封面不得继续作为客户预览。HTML 不追加封底预览，以免 PDF 重复；封底由最终 PDF 拼接阶段唯一追加。

## 六、渲染命令

```bash
python3 Strategy_Workflow/S10.AI智能品牌优化方案全景报告生成师.skill/scripts/pre_render_file_check.py \
  --brand "{brand}" --work-dir "outputs/{brand}"

python3 Strategy_Workflow/S10.AI智能品牌优化方案全景报告生成师.skill/scripts/render_panorama_report.py \
  --brand "{brand}" \
  --company-name "{company_name}" \
  --main-product "{main_product}" \
  --work-dir "outputs/{brand}" \
  --out-html "outputs/{brand}/04_final_report/S10_{brand}_AI智能品牌优化方案全景报告.html" \
  --out-pdf "outputs/{brand}/04_final_report/S10_{brand}_AI智能品牌优化方案全景报告.pdf" \
  --out-json "outputs/{brand}/04_final_report/S10_{brand}_全景报告数据.json"

python3 Strategy_Workflow/S10.AI智能品牌优化方案全景报告生成师.skill/scripts/template_compliance_checker.py \
  --html "outputs/{brand}/04_final_report/S10_{brand}_AI智能品牌优化方案全景报告.html" --strict
```

生产执行禁止增加 `--no-cover-stitch` 或 `--keep-html-cover`。这两个绕过语义无论是否仍被旧脚本识别，都不得用于标准 S10 产物；发现即视为生成失败。

## 七、与 S11 的边界

S10 负责内容、图表、来源承接与初始 HTML/PDF。S11 负责最终排版整理、分页优化和空白页检测。**每个分部的章节分隔页必须独立占一整页**，正文从下一页开始；分隔页不压缩、不优化，不得被合并为正文页首的一行小标题；S11 会自动豁免独立整页分隔页，不因其留白而判空白/稀疏。S10 完成后不得直接打包。

S10 初始 PDF 也必须使用固定官方封面/封底；S11 重新渲染时再次从客户 HTML 正文生成中间 PDF，并强制拼接同一官方两页模板。最终 S11 PDF 必须通过首尾视觉指纹门禁，而不能只信任“拼接成功”日志。

## 八、客户版禁用内容

不得出现：上游文件名或来源 `h1`、阶段输出头注、版本/日期/输入/原则/数据源说明、本地绝对路径、任务 ID、表格解析/内部调试字段、推理过程、CoT、未替换占位符、`None`、`待补齐`、`暂无`、`TODO`、样例客户字段、截图索引或空模块提示。

以下内容明确从客户版删除：问答树具体问题清单、“认知 · awareness 5 个核心问题”、“问题优先级与内容承接矩阵”、“30 条问题清单”、“质量与风险闸门”、话语手册句式模板、“危机与错误信息回应模板”、“下游注入规则”、“重校触发条件”、趋势机会坐标图、竞品心智地图，以及标题钩子独立章节。

## 九、官方封面/封底硬契约

1. 唯一允许的生产模板是 `templates/frontmind_cover_front_back.pdf`，必须恰好 2 页、每页 A4，且文件 SHA-256 必须等于 `e37c51f793649fcf561c80d80b4b80ae1f70c470ec8a6956523b1795f369872d`。
2. 最终页序必须是“模板第 1 页 + 去除 HTML 预览页后的正文 + 模板第 2 页”。不得保留官方封面和旧 HTML 封面的双封面。
3. `pdf_generation.cover_contract` 至少记录 `passed`、`template_filename`、`template_sha256`、`asset_pages`、`a4`、`html_cover_replaced`、`front_match`、`back_match`、`page_count_formula_passed`；客户 JSON 只保留文件名与哈希，不得写绝对路径。
4. 最终 PDF 第 1 页和最后 1 页须在固定 DPI、固定 A4 画布上栅格化，并分别与模板第 1/2 页计算视觉指纹；两项均为真才通过。
5. 模板缺失、非 2 页、尺寸不符、SHA 不符、无法栅格化、首尾指纹不符或只生成正文 PDF，均必须返回非零并阻断 S11/打包。

## 最终交付硬要求：全景报告 PDF 是主交付物

最终交付不能只返回 ZIP。ZIP 只是可选归档包，不能替代客户可读的全景报告 PDF。本工作流不生成《问题监控数据文件》PDF。

完成 S10/S11 和全部质量门后，必须将以下 PDF 作为独立文件/独立附件返回：

1. `{brand_id}_AI智能品牌优化方案全景报告.pdf`

`FrontMind_{brand_id}_AI全景报告交付包.zip` 只能作为第二个可选归档附件。若最终只返回 ZIP，视为交付失败，必须补充导出并上传全景报告 PDF。
