# S10 全景报告内容与版面 Blueprint 本工作流

## 目标

S10 不是 Markdown 拼接器，而是客户版咨询报告整合器。它必须先证明 S1-S9.8 的有效内容进入对应章节，再由 S11 负责成品版式整理。质量不再以固定页数、字数门控或模块数量衡量。每个分部的章节分隔页独立占一整页，正文从下一页开始，分隔页不压缩、不优化。

客户 HTML 首屏必须是固定官方封面 PDF 第 1 页的安全预览，不再使用旧 HTML 渐变封面。成品 PDF 必须在正文前后拼接固定官方两页 A4 模板：`frontmind_cover_front_back.pdf`，SHA-256=`e37c51f793649fcf561c80d80b4b80ae1f70c470ec8a6956523b1795f369872d`。

## 信息顺序原则

报告固定为 11 个正式分部。先完成“市场机会、品牌定位、品牌诊断、AI 可见性、用户意图、内容编排、语义/话语/视觉资产、风险管理”的诊断与资产设计；内容标题钩子紧随 12 周内容编排，作为第五部分内的小节；最后以第十部分 GEO 战略选择和第十一部分 GEO 业务流程收口。

## 必需内容模块

`panorama_report_template.html` 至少包含以下内容模块。模块可自然跨页或同页连续排布，不得为了凑页数机械分页：

1. 目录；
2. 经营层摘要；
3. 报告范围与诊断口径；
4. 品牌事实与可引用资产；
5. 市场趋势与品类机会摘要；
6. 趋势评分、机会含义与优先级表；
7. 品类增长叙事；
8. 品牌定位声明与价值三角；
9. 差异化矩阵；
10. 定位支撑与证据链；
11. 品牌诊断与 Gap；
12. AI 可见性诊断；
13. 平台可见性分析与图表；
14. 用户意图与问题路径；
15. 12 周内容日历；
16. 紧随日历的内容标题钩子小节；
17. 语义资产审计与五维达成度图；本章下半部分必须加入品牌信源覆盖与引用结构；
18. 话语资产与视觉资产；
19. 风险管理；
20. GEO 战略选择；
21. 优先行动清单；
22. GEO 业务流程图。

## 来源块规则

S1-S9 的十类正文来源必须各有且仅有一个 `.source-stage-block`：

```text
brand_facts
marketing
trends
positioning
diagnostic
semantic
verbal
visual
qa_architecture
enablement
```

覆盖检查在对应来源块内部进行，不能用其他章节重复出现的词句冒充。**覆盖率门已取消**：每个来源块只需存在且块内非空，覆盖率仅记录，不再作为阈值。

S8 问答树和问答矩阵保留为内部结构化输入，不进入客户正文；内容日历与 S9.8 标题钩子已生成即应渲染，且顺序必须为 `data-content-calendar` → `data-title-hooks`。

每个来源块必须清除上游 Markdown 带入的 `h1` 一级报告标题；最终 HTML 不得出现来源 `h1`。

## 图表规范

- S3 真实打分卡以评分表、机会含义和优先级表呈现，不生成趋势机会坐标图；
- AI 可见性图表必须由 S5.0 真实监控数据生成；
- 差异化矩阵必须由 S4 结构化定位数据生成，支持规范化后的嵌套/扁平竞品字段，并带 `data-differentiation-matrix` 标记；不得生成竞品心智地图；
- 语义资产五维条形图必须由 S5.5 真实评分卡生成；
- Top 信源条形图必须由已确认且后台对账通过的独立信源/引用分析表数据生成；客户版不展示三层对账/集中度 KPI，也不展示模型引用量图表；
- GEO 业务流程图必须真实进入第十一部分；
- 禁止硬编码历史样例品类、品牌或客户字段。

## 文本规范

- 不得出现 `……`、`...`、`GEO_A1: ……` 等省略号填充；
- 不得出现 `None`、`待补齐`、`暂无`、上游文件名、来源 `h1`、内部处理字段或推理过程；
- 不得出现阶段输出头注、版本/日期/输入/原则/数据源说明或 Unix/Windows 本地绝对路径；
- 不得出现问答树问题清单、问题优先级与内容承接矩阵、30 条问题清单、质量与风险闸门、句式模板、危机与错误信息回应模板、下游注入规则、重校触发条件、趋势机会坐标图、竞品心智地图或标题钩子独立分隔页；
- 来源局部标题须去除源文档编号；最终 11 个正式分部编号保持不变；
- 上游 Markdown 必须先清洗内部脚手架，但不得以固定字符数截断有效正文；
- 上游内容不足时必须在 S9 深度门阻断，禁止在 S10 使用空模块或通用套话补齐。

## 内容丰富度（字数门已取消）

- **不再要求客户可见正文达 24000 字符或模块达 18 个**；报告规模随各阶段实际产出自然形成；
- 建议每个主要章节尽量包含“结论、依据、影响、动作”四层信息（写作建议，非强制门控）；
- S10 不得把应保留的客户有效内容压缩成阶段摘要；上游内部结构化输入和明确删除项不直接拼入客户正文；
- 为避免为凑字数而填充重复内容，保留“重复行>25%”与“占位过多”等防灌水检查；
- S11 可以合并空白和优化分页，但不得删除已经嵌入的阶段内容，且必须保留每个分部的独立整页分隔页。

## 强校验

必须依次通过：

```bash
python3 ../S9.业务赋能规划师.skill/scripts/completeness_checker.py ...
python3 scripts/pre_render_file_check.py ...
python3 scripts/template_compliance_checker.py --html <S10 html> --report-json <S10 json> --strict
python3 ../S11.成品格式整理师.skill/scripts/layout_quality_checker.py --pdf <S10 pdf> --html <S10 html> --strict
```

阻断条件包括：

- 上游 25 个标准产物不完整或深度不足；
- 未替换模板占位符；
- 缺少 `client-ready-report-final-0`；
- 最终 HTML 仍出现 `.source-stage-block h1` 或其他来源一级标题；
- 来源块缺失、重复、错位或块内为空（不再因覆盖率不足而阻断）；
- 内容日历或标题钩子已生成但未渲染，或钩子未紧随日历；
- 差异化矩阵缺少真实数据或 `data-differentiation-matrix` 标记；
- 出现明确删除项、省略号占位、跨客户样例字段、内部头注、绝对路径、内部字段或任务状态；
- S11 检测到真正的空白页，或稀疏页超过 2 页（独立整页分隔页被自动豁免）。
- 官方模板缺失、非恰好 2 页 A4、SHA 不符、客户 HTML 仍显示旧封面，或最终 PDF 首尾视觉指纹未分别匹配官方封面/封底；
- 生产命令使用 `--no-cover-stitch` / `--keep-html-cover`，或 S11 报告 `no external cover`。
