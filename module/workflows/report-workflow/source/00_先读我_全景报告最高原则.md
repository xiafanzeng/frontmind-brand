## 一句话结论

你不是自由研究写作者，而是 **FrontMind Workflow 执行器**。本 Workflow 有且只有两条最高原则：

1. **先阅读流程和暂停点逻辑，作为最高原则。**  
   本工作流只有暂停点 1；未到暂停点不得自行越过；没有用户明确确认，不得调用后续阶段。S5.0 双表导入后自动确认并直接连跑。
2. **流程中每个研究型 S 阶段都必须调用 Wide Research，并把阶段文件落盘。**  
   聊天里说“已完成研究”不算完成；必须有 Markdown / JSON 产物和 `_execution/*_wide_research_manifest.json`。

## 暂停点规则：不可跳过（唯一暂停点 + S5.0 自动确认）

### 暂停点 1：固定双问题确认

位置：S4.8 完成之后、S5.0 监控数据来源执行之前。

必须先完成：S0.1、S1、S2、S3、S4、S4.8，且 S1-S4 均调用 Wide Research 并输出阶段文件与 manifest。

然后停止，向用户展示固定问题确认单。数据来源固定为墨力指数 API 自动取数，监测平台默认国内三平台（仅当项目输入或用户启动时明确指定其他平台/海外平台时按指定执行并记录），用户回复确认即可：

```text
确认以上两类 AI 监控问题，按默认国内三平台（豆包、元宝、千问）执行
```

在用户完成以上明确确认前，**不得导入表格，不得生成监控数据，不得写最终报告**。

### S5.0 双路径（本工作流 一键版）

- **墨力指数 API 自动取数（v3 起唯一路径）**。配置好根目录 `molizhishu_api.json` 后，用户在暂停点 1 确认双问题即可（确认脚本默认 `--monitoring-data-source molizhishu_api --platforms doubao,yuanbao,qianwen`；**监测平台默认国内三平台 豆包·元宝·千问，仅当项目输入或用户启动时明确指定其他平台/海外平台时按指定执行并记录**，`--list-platforms` 可查完整平台目录），随后运行 `fetch_molizhishu_monitoring.py`（同传 `--platforms`）：自动提交 2 问 × N 平台 × 5 次任务、轮询、拉取答案与引用、生成契约格式监控表与信源表两份 xlsx、自动调用两个导入器（`--data-source molizhishu_api`）完成导入与自动确认。详见 `Strategy_Workflow/shared/molizhishu-api-contract.md`。
- ~~路径 B（回退）：手动上传双表~~ **已于 v3 移除**：S5.0 唯一数据路径为墨力指数 API 自动取数，全程无需上传任何文件；API 失败保留真实错误并停止，不得以任何方式手工补数据。

### S5.0 之后：无数据确认暂停点，直接连跑

本工作流已取消数据确认暂停点（原暂停点 2）。用户在暂停点 1 确认固定双问题后，直接运行 API 自动取数（自动生成两份契约表格并自动导入）：

```bash
# AI 问答监控表
python3 Strategy_Workflow/S5.品牌诊断专家.skill/scripts/import_monitoring_spreadsheet.py ...

# 信源表（引用分析表）
python3 Strategy_Workflow/S5.品牌诊断专家.skill/scripts/import_citation_analysis_spreadsheet.py ...
```

API 自动生成的 AI 问答监控表与信源表（引用分析表）缺一不可。两份表格导入并通过固定范围/三层对账校验后，脚本自动写入 `data_confirmation_status=confirmed`，随后**直接连续执行 S5、S5.5、S6、S7、S8、S9、S9.8、S10、S11 直至最终全景报告**，不等待用户再次确认，也不再生成《问题监控数据文件》客户版 HTML/PDF/MD/TXT（监控数据只保留内部 JSON 供诊断与 S10 使用）。

如果成功答案数小于预期数：默认返回真实错误并停止，请用户重新上传完整表格；仅当用户明确接受部分数据时，才使用 `import_monitoring_spreadsheet.py --allow-partial-records` 写入 `partial_accepted=true` 后继续。

## Wide Research 不是“一次并行研究”，而是每个 S 阶段一次

必须逐阶段执行，不得合并为“并行研究完成”。

| 阶段 | 必须动作 |
|---|---|
| S1 | Wide Research → 品牌事实 JSON/MD → S1 manifest |
| S2 | Wide Research → 营销图谱 JSON/MD → S2 manifest |
| S3 | Wide Research → 趋势打分卡 JSON/MD → S3 manifest |
| S4 | Wide Research → 定位声明/定位报告 JSON/MD → S4 manifest |
| S5.0 | **墨力指数 API 自动取数生成的两份数据表格**：AI 问答监控表 + 信源表（引用分析表）；不是 Wide Research，不得模拟，路径B手动上传已移除 |
| S5 | Wide Research + 真实监控数据 → 诊断 JSON/MD/Gap 报告 → S5 manifest |
| S5.5 | Wide Research → 语义资产评分卡/报告 → S5.5 manifest |
| S6 | Wide Research → 话语 token/手册 → S6 manifest |
| S7 | Wide Research → 视觉 Prompt 包/报告 → S7 manifest |
| S8 | Wide Research → 问答树/矩阵/内容日历/落地页蓝图 → S8 manifest |
| S9 | Wide Research → 业务赋能建议包 → S9 manifest |
| S9.8 | Wide Research → 标题钩子 JSON → S9.8 manifest |

每个 manifest 必须包含：`stage_id`、`used_wide_research=true`、`research_queries`、`external_sources`、`generated_files`、`status=done`。

## S5.0 数据获取规则（v3：API 唯一路径）

S5.0 只能通过墨力指数 API 自动取数生成两份 `.xlsx`：AI 问答监控表与信源表（引用分析表），由 `fetch_molizhishu_monitoring.py` 自动生成并自动导入。前者按固定 2 个问题 × 实际平台数 × 5 次动态校验，后者按媒体/内容/问题三层引用总量对账；两份表格缺一不可。监测平台默认国内三平台（doubao/yuanbao/qianwen），仅当项目输入或用户启动时明确指定其他平台/海外平台时按指定执行。

绝对禁止：

```text
模拟 AI 平台对两个固定问题的回答数据
基于公开信息构造 30 条监控记录
由于未收到表格，我将手动整理监控答案
用 Wide Research 替代表格导入
mock / sample / manual records / synthetic data
```

若任一表格未上传、格式错误、记录不完整或引用数据无法对账，唯一正确动作是输出解析/完整性错误并停止，不能补造记录。

## 最终组装报告不得漏掉 S 阶段内容

S10 最终《AI智能品牌优化方案全景报告》必须采用“全文丰富组装模式”：S1-S9.8 的核心产物都要完整进入客户可读章节，不能只写浅层摘要，也不能用“详见附件”替代正文。S1 品牌事实、S2 用户意图、S3 趋势、S4 定位与竞品、S5 监控数据诊断、S5.5 语义资产、S6 话语体系、S7 视觉体系、S8 问答树/矩阵/内容日历、S9 行动与路线图、S9.8 标题钩子都必须完整承接。

> **字数门控已取消**：不再设置“90% 阶段覆盖率、36000 字符正文、24 个内容模块”等任何字数/覆盖率/模块数硬门。达标口径是：Wide Research 已执行、各 S 阶段真实内容已完整填入报告对应章节、无残留/占位/造假/重复灌水。保留“重复行>25%”与“占位过多”等防灌水检查，以免 Agent 为凑字数填充无意义重复内容。S11 只能整理格式，不能删内容，且必须保留每个分部的独立整页分隔页。

官方封面文件固定为 `Strategy_Workflow/S10.AI智能品牌优化方案全景报告生成师.skill/templates/frontmind_cover_front_back.pdf`，必须恰好为 2 页 A4，SHA-256 为 `e37c51f793649fcf561c80d80b4b80ae1f70c470ec8a6956523b1795f369872d`。生产交付禁止 `--no-cover-stitch` 与 `--keep-html-cover`。最终客户版还必须整节过滤“危机与错误信息回应模板”“下游注入规则”“重校触发条件”，并剥离来源局部标题编号，但保留最终 11 个正式分部编号。
