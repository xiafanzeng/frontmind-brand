# FrontMind Brand 报告工作流 · 双 HTML 版

版本 report-v3-web-html-2。本文件与 SHARED_CONTRACT.md 是当前可执行规范；原 source/Strategy_Workflow 中文件仅为历史方法及算法来源，不是运行指令。所有服务端编排、模型连接、采集和文件生成权限由应用控制。

## 研究主体
本次 input.brandName 与 input.context.subject 是研究及诊断主体。subject.scope 指定部门、产品或业务线时，所有研究、竞品和监测问题均围绕该范围；profile/母体企业资料只作相关背景。企业名、产品、竞品、结论不得写死。缺资料就继续公开研究并记录缺口，不增加资料确认暂停点。

## 执行顺序
S1 企业事实 → S2 营销图谱 → S3 品类趋势 → S4 品牌定位 → S4.8 核心产品与固定双问题 → 唯一业务确认 → S5.0 真实采集与校验 → S5 品牌诊断 → S5.5 语义资产 → S6 话语 → S7 视觉 → S8 12 周内容规划 → S9 业务行动 → S9.8 标题钩子 → S12 商业汇报内容 → S10 双 HTML 组装 → S11 两份 HTML 完整性与版面校验。

S1–S4、S5、S5.5、S6、S7、S8、S9、S9.8 都要独立执行有证据的研究；复用已有来源与文件，补充本阶段必要公开查询。S4.8 从已完成研究形成产品卡片。阶段正文、工具调用与结果、来源、中间文件、修订及错误持续保存并在网页展示；不能用虚构日志替代真实事件。

## 唯一确认点
只有 S4.8 完成后、S5.0 前暂停，由网页卡片一次确认核心产品、双问题和平台。Q1={核心产品}推荐；Q2={品牌名}有什么缺点和问题？默认豆包、元宝、千问，每问题每平台 5 次，共 30 份。不得扩大采集量或在模型工具中创建采集任务。S5.0 校验通过自动继续，不设第二次业务确认。中断沿用原任务 ID 和已成功结果，不重复付费提交。

## 输出与完成
仅两个最终交付文件：panorama.html 全景报告、briefing.html 汇报报告。均在线预览和下载，数字来自同一冻结 monitoring。任何阶段失败都保存真实错误；停止保留已完成研究与采集，绝不伪装完成。没有全阶段正文、完整采集、来源核验、两份可读 HTML 和实际视觉检查，不算完整交付。
