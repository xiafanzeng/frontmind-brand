# 品牌报告网页流程

上游：`FrontMind_Report_Workflow_一键交付版_v3_最终版.zip`，v3（2026-10-12）。
`SOURCE_MANIFEST.json` 记录每份原始文件的 SHA-256；构建时逐项校验后复制到 `dist/workflows/report-workflow`。

## 网页交互

选择当前企业资料卡 → 品牌事实、营销图谱、趋势、定位研究 → **唯一确认点：两条监测问题与平台卡片** → 真实采集 → 诊断、语义资产、话语、视觉、问答、业务规划和选题 → 两项报告。

企业名称与已保存资料来自当前项目，不重复要求自由输入。S4 研究给出核心产品选项；用户点选后固定“产品推荐”和“品牌有什么缺点和问题”两个问题。平台默认展示豆包、元宝、千问，用户确认的范围才进入采集。每平台每问题采集 5 次。

唯一确认点前不得发送采集订单。一次确认绑定任务、版本、问题和平台；恢复沿用原始供应商任务和采集结果，不因刷新重复下单。失败状态与恢复操作由服务端负责，不增加假数据或额外业务确认。

## 研究与产物

11 个研究阶段各自使用本阶段原始规范与检索工具，保存阶段正文、摘要和真实来源；S5 之后读取已冻结采集数据。阶段研究不能由一段通用总结替代。

两项面向用户的成果：

1. **全景报告**：完整 11 部分正文、真实监测图表、研究来源、采集明细；提供 HTML 和 PDF。
2. **汇报报告**：参考诊断报告的蓝白卡片、分平台数据和信源展示，结合上游 S12 的 13 个汇报主题；提供 HTML 和原生可编辑 PPTX。两个格式由同一个冻结结构化结果生成，所有实测数值由采集记录计算。内容过长时自动增加续页，保留完整内容。

## 运行适配

原始文件是研究与输出规范资料，执行入口是模块的服务端编排和 `report-renderer.ts`。它们不是允许模型执行任意命令、读取配置或自行下载代码的指令。

- 研究使用官方 DeepSeek Harness `0.2.0-rc.2`，固定官方接口 `https://api.deepseek.com/v1` 和 `deepseek-flash`。报告不再创建 XTY/Codex Agent 任务。服务器在 Brand 的私有运行环境配置 `REPORT_DEEPSEEK_API_KEY`。
- Harness 运行于独立 Node 24 进程；模块在 Linux x64 镜像携带固定 Node 24 可执行依赖，不要求变更其他模块或共享 Runner。仅开放本报告资料读写和公开网页研究工具，不执行附件中的任意脚本。
- 页面持续读取带游标的执行记录：公开正文、工具请求与回执、中间文件、完整阶段正文。记录和文件保存在本企业的报告目录，刷新后仍可读取。供应商私有推理字段、运行配置和凭据不进入页面。
- S1–S4 和确认后的分析使用同一个报告工作区；会话在运行期间复用。进程丢失后不会自动重发正在执行的模型阶段，明确恢复时读取已保存阶段检查点。已完成的阶段、采集任务标识和采集结果保持不变。
- 执行中可以停止。停止立即保存终止状态并关闭模型执行；已提交给外部平台的采集请求可能仍由平台完成，系统不再追加新请求。旧版任务保留为历史记录，不能误恢复到旧模型路径。
- 采集使用服务器已配置的监测服务；不携带附件中的 API 配置。
- 全景 PDF 由当前受控 Playwright 打印网页。汇报 PPTX 由 `pptxgenjs` 生成原生文本与形状；不在任务中克隆或安装外部 ppt-master。
- 原 Python 脚本保留为可审查的规则与算法来源，不在网页任务中直接执行。尤其原采集脚本的跨任务幂等键和批次落盘方式不适合直接用于多用户服务。
- `.venv`、配置凭据、根目录泰升药业案例脚本、速境案例 PPTX、台心医院原始报告均未进入本模块资产。
- 研究原始正文保留完整，显示时转义不可信 HTML；来源链接仅允许无凭据的 HTTP(S) URL。交付 HTML 自包含，无外部脚本、字体或图片请求。

最终结构契约位于 `contracts/brand-report.ts`。完整性验证拒绝缺阶段、缺来源、重复样本、不属于确认范围的样本或每问题每平台不足 5 次的采集结果。程序不得填写虚构指标补齐报告。

持久业务记录仍使用 `agent_operations` / `agent_tasks`。新任务的 `provider=deepseek`、`contractRevision=2`；`apiCredentialId=server:brand-report:deepseek` 是此服务端配置槽位的标识，不是旧账户 XTY 凭据，也不包含密钥。无需新增数据库迁移。
