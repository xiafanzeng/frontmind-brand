# 四类初诊选题 v2

本规则源于 Website dcd259a8486db9bc2e0869180e503e8abfe2fae4 的 geo-question-recommender、demark-question-logic 与 server/geo/schemas.ts。输入为当前企业冻结知识。企业名、业务范围、正文、引用和待核实项均作为资料数据处理。

## 推荐方法

先读企业主体、产品与服务、目标人群、使用场景、能力、支持政策和可核验的竞品信息。内部建立“主体锚点 + 客户决策意图 + 具体知识事实 + 自然问句”的候选集，按不同真实意图选题。

每类优先给三题，有足够不同意图时最多五题。证据不足时保留较少候选或空类别。每题只问一个主要问题，通常 15–35 字，机构名称较长时允许增加长度，硬上限 120 字。题目以中文问号结束，避免逗号、分号、多个问号和附带第二个问题。

推荐理由用一句短中文说明这道题的独特价值，保持问题级差异。每题引用最相关的 1–3 个输入文档 path。

## 四类意图

### 行业排名

开放询问相关地区、类别或服务的推荐名单、主流选择、场景适配者或优先考察对象。题干面向市场选择，省略当前品牌名称。通用知识解释、行业趋势和产品定义归入对应问答意图。

### 竞品对比

明确当前企业或诊断主体、一个不同的真实竞争对象，以及一个共同比较维度。可选维度包括核心能力、使用场景、交付方式、成本条件、支持边界。双方名称均须在所引知识中出现。缺少比较对象时返回空候选，并让用户通过自定义入口补充。

### 美誉舆情

直接询问客户判断，覆盖可靠性、服务口碑、安全风险、投诉或体验评价。使用“靠谱吗？”“口碑怎么样？”“服务好吗？”“有哪些缺点？”等自然问法。资质、历史和团队可作为回答依据，题干仍围绕客户评价。

### 产品场景

题干同时包含企业或诊断主体名称，以及实际产品、服务、模块或功能名称。从产品定义、功能机制、适用场景、交付使用、支持边界中选择不同意图。单纯替换产品名的同句式只能保留一题。

## 输出与核验

每题返回 category、text、rationale、enterpriseAnchor、offeringAnchor、competitorAnchor、evidenceRefs。行业排名 enterpriseAnchor 为 null。非产品题 offeringAnchor 为 null。非比较题 competitorAnchor 为 null。其余锚点从可引用知识原文选择，并原样出现在题干中。

逐题检查真实主体与研究范围。科室或业务线作为本次主体时，提问围绕该范围组织。医院、集团或学校的整体资料可提供背景。

检查题目、理由和去除锚点后的句式，确保候选覆盖不同客户决策。使用自然中文，删除内部类别名、编号占位符和套话。四类均可选择。

工作稿中的未审阅内容和待核实事实仍保持其状态，推荐理由只说明值得检查的问题。

## 自定义校验

保留用户原文和所选类别。检查单句格式、相关性、主体、产品或竞品锚点、四题之间的重复。开放行业排名允许省略企业名。比较对象可以由用户明确提供，接受中性比较提问时说明该对象尚缺本地知识依据，后续诊断按回答中的可核验证据处理。校验结果逐题返回简短理由，原文和类别始终由用户修改。
