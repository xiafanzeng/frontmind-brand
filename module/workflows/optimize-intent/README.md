# 优化问题的真实 Skill 流程

正式优化工作台通过账户已有模型 API，基于当前品牌知识生成评估和方案。行业回答要点、评分理由、问题改写和知识修改建议均由模型生成；服务端负责证据核对、评分口径校验和实际写入。开发预览仍使用明确标识的演示数据，不能作为真实模型调用证据。

## 运行依赖

Dashboard 初始化现有品牌全域词库服务时，将已经认证的账户、凭据、数据库、项目写入锁、模型客户端和资源记账端口同时装配给优化运行时。新流程复用现有 `globalKeywords` 服务权限。浏览器只提交问题标识和清单修订号，不提交 API 密钥或知识正文。正式宿主需已有优化清单迁移及 Core 任务表；此改造不增加数据库迁移。

构建将 Skill 正文复制到模块发布目录。每次任务冻结 Skill 正文、知识节点、所选问题和完整候选清单，计算规范 JSON 哈希（内容摘要；不受数据库对象字段重排影响）。服务器将冻结数据和 Skill 正文打包为 ZIP，调用同一账户的文件上传、任务创建与消息查询 API。

## 任务与结果

1. 在同一数据库事务内预留优化清单任务、Core 操作和 Core 任务，冻结输入及凭据版本。
2. 事务结束后上传附件。创建任务前持久化“创建结果待确认”状态；此后任何重放均只查询原任务，不自动重复创建。
3. 页面轮询任务。刷新后可恢复查询；切换项目或离开页面终止当前页面的轮询，服务器保留任务。
4. 模型返回严格 JSON。结果必须匹配任务标识、输入哈希和完整所选问题集合。原文引用必须真实存在于指定节点；未确认节点不能计为充分支撑。
5. 知识支撑分按回答要点状态统一计算并校验，综合分按六维平均值校验。任务期间知识或问题变化则拒收结果，提示重新评估。
6. 方案只能引用当前可编辑节点。节点正文变更默认不勾选，用户审核、修改、采纳后才能执行。执行前还会核对方案所依据的知识与问题是否过期。
7. 执行继续调用已有知识节点保存接口，并保留原文、变更回执和撤销冲突保护。执行和撤销后分别启动真实模型重评；创建资料待办不等于知识补齐。

任务采用数据库租约防止并发重复派发。创建结果不确定时预留两分钟查询恢复；模型结束后预留两分钟等待结构化结果；总体超时三十分钟。超时或输出不合格时显示失败，正式流程不会回退到规则评分。

## 验证范围

自动化测试用模型 API 测试替身验证真实调用协议、任务预留、重放、未知创建恢复、输入冻结、证据拒收、执行与撤销后重评、跨项目轮询终止。类型检查及模块构建验证发布目录内 Skill 可加载。它们不代表已经使用客户凭据完成线上模型验收；线上效果需在有权限的账户中实际生成评估及方案后确认。
